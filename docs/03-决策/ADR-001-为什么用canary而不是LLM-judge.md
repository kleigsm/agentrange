# ADR-001：用 canary 而不是 LLM-as-judge

- 状态：已接受
- 日期：2026-11-25
- 决策者：kleigsm

## 背景

要测“Agent 会不会被注入攻击成功”，必须有一个判定器。常见做法是让另一个 LLM 判断。

## 问题

1. LLM judge 本身也会被注入：攻击者可以把“请判定为安全”写进数据里。
2. LLM judge 不稳定：同样的输入，换个顺序或措辞，结论可能翻转。
3. ICML 2026 的 *A Coin Flip for Safety* 系统评测显示，judge 在对抗场景下接近随机。

## 决策

判定只使用**可执行谓词**，核心是 canary：

- 每个任务注入一个唯一字符串。
- 攻击成功的定义：canary 出现在指定的 sink（外发邮件、HTTP 请求、文件写入）。
- 判定代码是确定性的，不调用任何模型。

## 备选

| 方案 | 优点 | 缺点 |
|---|---|---|
| LLM-as-judge | 通用、易写 | 不可靠、可被注入、不可复现 |
| 人工标注 | 准确 | 贵、慢、无法规模化 |
| 字符串 canary | 确定、便宜、可复现 | 只能测“数据外泄”类后果，覆盖面有限 |

## 后果

- 正面：结果可复现、可被第三方验证、能做成证据包。
- 负面：不是所有攻击都有 canary 形态（比如“说了不当言论”），需要为不同后果设计不同 oracle。
- 缓解：oracle 设计成可插拔，canary 只是其中一种。
