# 2026-11-28 工具输出消毒

## 想法

结构型注入的根因不是“模型不听话”，而是**工具结果里的特殊 token 被聊天模板当成了结构**。

那就不让它们进去：在工具结果进入模型之前，把 `<|...|>` 中和成 `[TOKEN]`，把 `[INST]` 中和成 `[INST]`。

## 实现

- `defenses/tool_output_sanitizer.py`
- `agent.py` 在工具结果回填前调用 `defense.sanitize(result)`
- 递归处理 dict / list / str

四个格子全部归零，utility 都是 1.0。

## 解读

- **跨注入面有效**：正文和主题都被压到 0
- **跨模型/跨模板有效**：Qwen 的 `<|...|>` 和 Mistral 的 `[INST]` 都压到 0
- **不改变可用性**：模型仍读到内容（exposed 100%），正常任务 utility 1.0
- **不依赖模型服从**：代码确定性替换，不像提示词加固会被绕过

注意 018（纯文本主题）的 0.00 **不能说明消毒能防纯文本**：消毒根本不改纯文本；基线只有 0.10，这次 10 次没中是抽样。纯文本注入需要内容层防御。

## 为什么它比三层防御更“根因”

三层防御（allowlist / redaction / recovery）是在**动作层**补救；消毒是在**入口层**消除根因。

两者不冲突：

- 消毒：阻止结构 token 进入模型
- allowlist：阻止不该发的收件人
- redaction：阻止不该发的内容
- recovery：拦截后恢复任务

## 踩坑：`[INST]` → `[INST]` 等于没中和

第一次在 Mistral（013）上跑消毒，ASR 仍是 **1.00**。

原因：消毒把 `[INST]` / `[/INST]` 都替换成了 `[INST]`，而 `[INST]` 本身**就是** Mistral 的结构 token。替换后的文本里仍然有一个合法 token，模型照样能接上。

修复：替换成非 token 的 `【INST】`（全角括号）。

这个坑说明：**消毒的替换目标本身必须是“非结构”的**，否则只是换了个 token。`<|...|>` → `[TOKEN]` 是安全的，因为 `[TOKEN]` 不是任何模型的结构 token。

## 局限

- 只测了 Qwen2.5-3B，n=10
- **纯文本注入（018）不会被消毒**：它没有特殊 token，需要内容层防御
- 合法数据里如果有 `<|...|>`（比如讲 token 的文章），会被改掉
- 没测 Mistral / Llama 的 `[INST]` / `<|start_header_id|>` 变体（消毒规则已覆盖，但没跑）

## 一句话

> **别让不可信的数据带着结构 token 进入模型。**
