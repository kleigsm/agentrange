# 术语表

| 术语 | 一句话解释 | 在本项目里 |
|---|---|---|
| Agent | 会自己调用工具、分多步完成任务的 AI 程序 | 被测试的对象 |
| Tool calling | 模型输出“我要调用某个函数”，程序执行后把结果还给它 | 攻击的入口 |
| Prompt injection | 把指令伪装成数据，骗模型执行 | 我们要测的攻击 |
| 直接注入 | 用户直接在对话框里注入 | 本项目不做（已被研究透） |
| 间接注入 | 指令藏在邮件 / 网页 / 文件里，Agent 读取时中招 | 核心攻击类型 |
| Canary | 一个唯一字符串，用来检测数据是否泄漏 | 判定依据 |
| Oracle | 判定“攻击是否成功”的可执行规则 | 替代 LLM judge |
| LLM-as-judge | 用另一个大模型当裁判 | 我们不用的方案 |
| ASR | Attack Success Rate，攻击成功率 | 核心指标 |
| Utility | 正常任务完成率 | 防误伤的指标 |
| Guardrail | 输入 / 输出侧的安检模型 | 防御之一 |
| Capability sandbox | 只给 Agent 必需的权限，从架构上限制后果 | 最强防御 |
| Trajectory | Agent 的完整执行轨迹（消息、工具调用） | 证据包核心 |
| Evidence Pack | 可独立验证的证据包 | 项目的产出物 |
| Benchmark | 统一任务 + 统一判定 + 可比较的结果 | 项目的形态 |
| Harness | 批量跑任务、收集结果、算指标的框架 | 要写的代码 |
