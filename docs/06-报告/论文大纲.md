# 论文大纲（草稿）

## 工作标题

**AgentRange: A Reproducible Benchmark for Tool-Using LLM Agents — and Why Textual Defenses Backfire**

备选：

- *The Layer Below the Prompt: Structural Injection and the Limits of Textual Defenses in Tool-Using Agents*
- *Canary, Not Judge: Measuring Agent Injection with Executable Oracles*

## Abstract（要点）

1. Agent 红队结果普遍不可复现：LLM judge 不稳定、攻击常不在关键路径、attempt ≠ success。
2. 提出 AgentRange：可执行 canary oracle + 三指标分离（exposed / ASR / policy violation / utility）。
3. 在 7 个本地模型、15 个任务、6 种防御上验证。
4. 发现：
   - 结构型注入是模板相关的（Qwen 0.20–0.80、Mistral 1.00、Llama 0.00）
   - 文本加固会反噬（0.50 → 1.00）
   - 单一 allowlist 保安全但 utility 归零
   - 三层 who/what/after 达到 0 / 0 / 1.0
5. 结论：防御要落在**角色/权限层**，不是文本层。

## 1. Introduction

- 动机：Agent 开始有工具权限，注入的后果从“说错话”变成“做错事”。
- 问题：现有评测不可复现、指标混淆。
- 贡献：
  1. 可执行 oracle + 指标分离
  2. 结构型注入的模板相关性
  3. 文本防御反噬的实证
  4. who/what/after 三层防御

## 2. Related Work

- Prompt injection（直接/间接）
- Agent 安全基准：InjecAgent、AgentDojo、ASB 等
- LLM-as-judge 的可靠性
- 防御：prompt hardening、guardrails、capability sandbox、human-in-the-loop
- 差距：缺少“可执行 oracle + utility 同时测”的基准

## 3. Benchmark Design

### 3.1 环境
- email assistant，6 工具，SQLite 邮箱
- 任务模板：目标、种子、canary、攻击面、benign check

### 3.2 Oracle
- canary in sink（读真实 sent 表）
- policy violation（收件人 vs contacts）
- exposure（邮件正文是否被读）
- utility（benign check）

### 3.3 统计
- Wilson 95% CI
- 条件 ASR（ASR | exposed）

### 3.4 评测有效性
- 六个陷阱（关键路径、attempt≠success、utility 依赖任务信息、中性基线、正对照、CI）

## 6. Discussion

- 为什么文本防御会失效：层错位 + 动作词激惹
- 为什么 allowlist 会漏：只管收件人，不管内容
- 为什么 Llama 抵抗：工具结果封装为 `ipython`
- 对系统设计者的建议：把“角色”和“权限”作为一等公民

## 7. Limitations

- 样本小（5–20）
- 本地小模型，无前沿 API
- 单一环境/注入面
- 因果实验有混淆（模板变了，能力也变了）
- 恢复提示是 harness 注入，不是模型能力

## 8. Conclusion

- 一句话：**防御的终点不是拦住，是拦住之后还能继续干活。**
