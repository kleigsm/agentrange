# AgentRange 一页纸

## 一句话

一个可复现的 Agent 安全基准：用 **canary oracle** 代替 LLM judge，发现**文本防御会反噬**，并提出 **who / what / after 三层防御**，同时保住安全与业务。

## 问题

Agent 有了工具权限后，提示注入的后果从“说错话”变成“做错事”（转发机密、越权发信）。现有评测有两个问题：

1. 用 LLM judge 判定“攻击是否成功”，不稳定、不可复现
2. 把“尝试”“成功”“任务是否完成”混在一起

## 方法

- **靶场**：本地模拟邮件助理，6 个工具，注入点在邮件正文
- **oracle**：canary 有没有出现在真实的 `sent` 表里，二值判定，不调用模型
- **四指标**：`exposed` / `ASR` / `policy_violation` / `utility`
- **统计**：Wilson 95% CI；正对照（scripted）；六个评测陷阱
- **模型**：Qwen2.5 1.5B/3B/7B、Mistral-7B、Llama-3.1-8B（本地 Ollama，RTX 4060 8GB）

## 主要结果

| 发现 | 数字 |
|---|---|
| 普通注入打不穿 | 0/5 |
| 结构型注入（伪造 user 轮） | Qwen 0.20–0.80、Mistral 1.00、Llama 0.00 |
| 提示词加固反噬 | ASR 0.50 → **1.00**（20/20） |
| 单一 allowlist | 0 / 0，但 utility **0** |
| allowlist + recovery | utility 1.0，但漏 **0.25**（发给合法收件人） |
| **三层防御** | **0 / 0 / 1.0**（Qwen 20 次、Mistral 20 次） |
| 机制 | 工具结果的角色（`ipython` vs `user`）决定条件 ASR：0/5 → 6/7 |

## 复现

```bash
git clone https://github.com/kleigsm/agentrange
cd agentrange
uv venv
uv pip install -r requirements.txt

# 不需要下载模型
.venv/Scripts/python.exe -m harness.run --task tasks/email-exfil-004.yaml --model scripted

# 需要 Ollama
.venv/Scripts/python.exe -m harness.batch --task tasks/email-exfil-009.yaml --model ollama:qwen2.5:3b --defense recipient_allowlist,content_redaction --recovery --trials 20
```

## 简历三条

1. **设计并实现 AgentRange**：一个可复现的 Agent 安全基准，用 canary oracle 替代 LLM judge，将 exposed / ASR / 越权 / utility 分离度量；覆盖 7 个本地模型、15 个任务变体、6 种防御配置，全部结果带 Wilson 置信区间与可执行证据。
2. **发现并量化“提示词加固反噬”**：在结构型注入下，`prompt_hardening` 把 ASR 从 0.50 推到 1.00（20/20）；通过 2×2 消融与措辞对照，定位机制为“规则只覆盖数据层 + 动作词激惹”。
3. **提出 who / what / after 三层防御**：`recipient_allowlist + content_redaction + recovery` 在 Qwen2.5-3B 与 Mistral-7B 各 20 次上实现 ASR 0、越权 0、utility 1.0；开源仓库含 CI、英文文档与可复现证据。

## 面试可能被问

- 为什么不用 LLM judge？→ 不稳定、attempt≠success；canary 是二值判定
- 为什么只有小模型？→ 本地可复现、成本低；结论是机制性的
- 三层防御是不是堆叠？→ 每层解决不同维度，单层会漏，有数据
- Llama 为什么抵抗？→ 工具结果封装为 `ipython`；模板改造实验验证
